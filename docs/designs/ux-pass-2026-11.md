# UX pass, November 2026

Sri's seven issues from 2026-11-15, the audit behind them, and the proposed
fixes. Status: **accepted 2026-11-15**; Sri took the recommendation on all four decisions (marked ✅).

## What Temple is for, and what each screen owes that

You run many long-lived agent sessions across a handful of projects and
four or five machines, mostly from the keyboard, with a terminal filling the
window. At any moment you need to know three things without reading:

1. **Which sessions are open**, and which of them want you (waiting, running).
2. **Where you are**: this project, on this machine.
3. **How to get back to something** you closed recently.

Everything else (history, archive, settings, shortcuts, hosts) is
occasional and should sit one step away, not on the main surfaces.

neither).

## Proposals

### 1. One way to show "project on machine" (fixes A1)

Wherever a project is named, the project name is the main line and the
machine is a second, quieter line (or, where there is no room for a second
line, a separate trailing label that truncates **before** the name does).
This Mac is never named unless another machine appears on the same surface,
so a setup with no hosts looks exactly as it does today.

- **⌘P tiles**: tiles widen from 96pt to 120pt. Lines: folder, project name,
  machine name (small, secondary), then "2 sessions" / "current". When no
  tile is on another machine, there is no machine line at all.
- **⌃⇥, home page, tab-bar project menu**: name, then the machine as a
  separate label, never one string.

### 2. ⌃⇥ looks like a switcher, not a search (fixes A6, A7)

✅ **Decision 1 — shape: cards.** **cards, like ⌘P.** Both hold-a-key
switchers become the same family: a centred panel of cards you tab through.
Each card: agent badge and activity dot on top, the session title (up to two
lines), then project and machine. Up to five cards per row, wrapping to a
second row; the panel is centred in the window, not pinned under the title
bar where ⌘K lives. Colour marks become a thin bar on the card's edge (as in
the sidebar), never a fill. A one-line hint under the cards: "Release ⌃ to
switch". The alternative is to keep a vertical list but centre it, drop the
⌘K look, and add the hint; cheaper, but it still reads as a list of results.

### 3. The sidebar shows what is open, then what is recent (fixes A2–A5, issue 6)

Inside every project:

```
⌄ MENTES-AI ───────────────────────── +
  ✳ image review thread              ●     ← open (tab order), full strength
  ✳ code review metrics              ●
                                            ← 8pt gap, no label
  ✳ terminal tab title              2h     ← closed in the last 7 days,
  ✳ merge instruction sync          1d        newest first, age on the right
  ✳ fxtwitter post lookup           4d
    Show 38 older                          ← reveals 10 at a time
```

- **Open** sessions come first, in the same order as their tabs, with the
  activity dot as today.
- **Recent** closed sessions follow, newest first, only if their last
  activity is within the window (default 7 days), up to 6 rows in total for
  the project. The age sits where an open row's dot sits, so the trailing
  column always answers "what state is this in".
- **Older** sessions hide behind "Show N older" (10 at a time), as today.
- A project with nothing open and nothing recent shows its header and
  "Show N older" only.
- Pinned sessions keep their own section at the top of the rail.

**Moving rows.** Today the order is frozen at launch so a row never moves
under the pointer. New rule: the order updates live (a tab opening moves
its row into the open group, a session closing moves it into recent), but
**never while the pointer is over the sidebar**; pending moves land when
the pointer leaves. Mail does this with new messages.

**Sort, group, filter.** One button in the rail's title-bar actions (beside
search), the filter icon Mail and Notes use, opens a menu:

```
Sort Projects By
  ✓ Recent Activity      ← live, as above
    Custom Order         ← your drag order (today's behaviour)
    Name
Group By
  ✓ Project
    Machine              ← machines as top-level groups, projects inside
Show
  ✓ Open and Recent
    Open Only
Recent Means
    Last Day
  ✓ Last Week
    Last Month
```

Dragging a project header switches the sort to Custom Order (as Finder
does when you drag an icon in a sorted view, it asks; we just switch, and
the menu shows it). The choice persists.

✅ **Decision 2 — "activity" means last activity.** You listed "activity" as a sort. Two
readings: (a) **last activity** (what Recent Activity above already is), or
(b) **needs you first**: projects with a session waiting for you or running
go to the top. Recommended: (a) as the sort, and make (b) unnecessary by
the open group plus the attention dot. Say if you meant (b).

### 4. The home page: start, continue, nothing else (fixes A8, A9)

```
  [Temple mark]  Temple
                 Where agents answer the call.

  START ──────────────────────────────────────────
  ✳ New Claude Code session in mentes-ai      ⌘T
  ◎ New Codex session in mentes-ai            ⌥⌘T
  ⊕ New session in another project or machine… ⌘N

  CONTINUE ───────────────────────────────────────
  ✳ image review thread        mentes-ai         2h
  ✳ auth incident cleanup      vapi-ops · mac-work  5h
  ✳ audit pruning phase        personal-ops      1d
  …5 rows: your most recent sessions that aren't open

  ⌘K Search   ⌘Y History   ⌘/ Shortcuts   ⌘, Settings
```

- Start rows name the project they start in. With no project yet, they say
  "…in a folder…" and ask.
- One row covers every other project and every machine: the ⌘N picker,
  which already lists projects, folders and hosts. No per-host rows.
- Continue lists sessions, not projects: resuming is the common act.
- Palette, History, Archived, Shortcuts, Settings become one quiet line of
  key hints at the bottom: still taught, no longer competing.

### 5. Hosts get their own window (fixes A10, A11)

A **Hosts** window in the shape of macOS Internet Accounts: a list on the
left, details on the right, + and − under the list.

```
┌ Hosts ───────────────────────────────────────────────────┐
│ ● mac-mini-personal   │ mac-mini-personal                │
│ ● mac-work            │ from ~/.ssh/config   Open config │
│ ○ masterblaster       │                                  │
│ ● masterblaster-mentes│ Connected · 2 sessions running   │
│                       │ ✳ designer audit follow-up       │
│                       │ ✳ recent changes pulled          │
│                       │                                  │
│ + −                   │ Test Connection                  │
└──────────────────────────────────────────────────────────┘
```

- Status per host from what Temple actually knows: connected (a session or
  the engine reached it), couldn't connect (with the reason), or not used
  yet. "Test Connection" stays for an explicit check.
- Running sessions on the selected host are listed inline (today's
  "Running sessions on X…" sheet).
- + is today's Add host sheet; − is Remove with its "still running" prompt.
- Opened from: a "Manage Hosts…" button where the Hosts section was in
  Settings, a ⌘K command, and the context menu of any machine heading in the
  sidebar. No new shortcut.
- With no host added, the Settings button is still the one remote thing
  you see (ADR-036's rule moves with it).

### 6. Smaller fixes from the audit

- History: "Open Session by ID…" moves into the header row beside Refresh
  (A12).

## Order of work

1. Shared project-on-machine label (1), then ⌘P and the tab-bar menu.
2. Sidebar open/recent split and the live-but-not-under-the-pointer order (3).
3. Sidebar sort/group/filter menu (3).
4. ⌃⇥ cards (2).
5. Home page (4).
6. Hosts window (5).
7. History header (6).

Each step: tests, snapshots in light and dark from `make demo` (extended
with open tabs and a fake host so the new states are visible), FEATURES.md
and an ADR, and the copy cold-read for every changed label.

## As built (2026-11-15)

All seven steps shipped as ADR-042, with these changes from the proposal:

- **The cold read** (a fresh Fable, no repo access) renamed the View Options
  menu: Group By became a single **Group by Host** toggle (both old choices
  grouped by project), Recent Means folded into **Show** (Open Only, Open
  and Last Day / Week / Month), Custom Order became **Manual Order**; Show
  N more became **Show N older**; the home page's hints read **Search
  Sessions** and **Keyboard Shortcuts**; "machine" became "host" in new
  labels; the open row's dot gained a tooltip.
- **Hosts is a sheet, not a window.** Temple is single-window and closing
  its window quits (AGENTS.md); a second window would sit outside that
  logic. Same list-and-detail shape.
- **Host status** is still the last connection test's. Temple's remote
  engine knows when a host was last reached, but that state is private to
  the remote source; surfacing it is a follow-up.

## Round 2 (owner's review of the demo, 2026-11-16)

| Owner's note | Change |
|---|---|
| The gap between open and closed sessions is inconsistent spacing | Open sessions sit in one thin outlined box per project, drawn behind the rows: even 32 pt pitch, same columns. Outline, not fill: a filled one-row box was the selected row's shape |
| Rename Manual Order | **Custom** |
| "Open and Last Day / Week / Month" is bad UX | One toggle, **Show Open Sessions Only**; "recent" is a fixed 7 days |
| Group by Host headings can't fold | They fold and unfold like project headings (not persisted, as projects aren't) |
| Sessions need their own sort | **Sort Sessions By**: Recent Activity, Name, Date Started (new `started_at`, v15), Custom (drag a closed session within its project) |
| The ⌃⇥ switcher is pretty bad | Cards kept (no live preview), redone: a header line (agent, project, host, current, activity), the title as the body, no fill but the selection, four to a row so the panel fits a 900 pt window, 16 pt panel corners |

The design pass (frontend-design skill) set one type scale for the new
surfaces (11 / 12 / 13 / 15 / 26; the odd 9.5, 10, 10.5, 11.5, 12.5, 14.5
and 17 are gone from them), radius by level (7 rows, 10 boxes and cards, 16
panels), and fixed the Hosts sheet's inverted hierarchy (a 17 pt host name
under a 15 pt sheet title). Kept on purpose, as the owner's earlier
decisions: 32 pt rows, 13 pt type, colour agent badges, tracked uppercase
project headings.

## Round 3 (owner's review, 2026-11-16)

Options drafted by a design teammate (Opus, frontend-design skill), the
owner picked the recommended one for each.

- **Host above project without indenting.** The host heading is a title,
  not a label: 13 semibold primary, sentence case, its glyph in the chevron
  column so its name sits on the project names' column, its fold chevron at
  the trailing edge, a full-width hairline above every host after the first
  (20 above, 4 below), and the first project under it 4 pt below instead of
  the 12 pt group gap. Rejected: a pinned shaded band (reads as a selected
  row, and pinned views under the title bar are the titlebar-inset trap's
  ground) and indent guides (clutter).
- **Open rows without the box.** The owner found the outlined box
  "okay-ish". Gray marks the closed rows, not the open ones: gray means
  "less available" everywhere on the Mac, and graying open rows collided
  with the missing-transcript tone. `Palette.closedRowText` (0.58 light,
  0.56 dark; about 4.6:1 and 6:1), then (owner) two tones only: a third, lighter tone for a missing transcript read as "closed" and made the closed rows beside it read as open; such a row now reads as any closed one, its badge faded (hiding it was weighed and not done: the ADR-030 sweep archives what it can prove gone, and what stays is mostly a person's Restore),
  open rows primary; the trailing dot vs age is the second cue. The open
  rows the owner saw grayed in the demo were transcript-missing rows (new
  tabs with no transcript yet), not the open style.
- **⌃⇥ is a list again**, reversing round 1's cards: a 196×92 card held a
  one-line title, so ~40% of each card was empty and the selection painted
  that slab. A 480 pt list centred in the window, single 36 pt lines (badge,
  title, project and host trailing, "this tab" or the activity dot), up to
  nine, no field: not the old ⌘K twin (top-anchored, ⌘K's width, two-line
  rows, a field-shaped gap).
- **Hosts manager.** 760×500, System Settings' shape (title over a shaded
  list column, no title bar), detail in labeled groups with each action on
  its fact's row (Address; Source with Edit… or Open ~/.ssh/config; Status
  with Test connection), and Running sessions filled in place by Show
  running sessions (`RemoteSessionsList`, shared with the sheet; the
  manager's request counts as live for the gate,
  `AppModel.hostsManagerSessions`), never on selection: a host may ask for
  a passphrase. The hostname is no longer repeated in the button. Buttons
  use `TemplePrimaryButtonStyle` (graphite `Palette.accent` with
  `Palette.onAccent` text) and `TempleButtonStyle` (`controlFill`), not
  the system blue AppKit gives a default button.
- **Copy.** Cold-read by a fresh Opus: "Set up in: Temple" read as an
  installation step (now "Source: Added in Temple"), "Not checked" as a
  checkbox state (now "Not checked yet").
