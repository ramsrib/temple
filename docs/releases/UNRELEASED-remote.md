## What's new

- **Sessions on another machine.** Start a Claude Code or Codex session in a folder on a host you reach with ssh, and work in it in a Temple tab like a local one. Sessions on another machine appear once you add a host in Settings ▸ Hosts; until then nothing about Temple changes. Temple runs your own ssh and never stores a password or a key; ssh asks what it needs (a host key, a password, a second factor) where you can see it. Settings' Claude and Codex arguments apply on hosts too, `--dangerously-skip-permissions` included.
- **Setting up a host.** Add hosts in Settings ▸ Hosts, from your `~/.ssh/config` or by address, and use **Test connection** to check `claude`, `codex` and tmux on the host and see what each said. Then start a session from ⌘N (**Folder on <host>…**), the launcher (**New session on <host>…**) or a host project's `+`. Sessions on a host sit under their folder with the host's name beneath it, reopen from the sidebar, ⌘K and History, come back as tabs after a relaunch, and fill a missing title, folder or date from their transcript on the host.
- **Agents on a host keep running when Temple quits.** Each one runs in a hidden tmux server of Temple's own on the host (`tmux -L temple`), so a dropped connection, a sleeping Mac or a quit does not end it, and opening the session again reconnects to it. Closing a tab works as it does locally: an idle agent is stopped, and a working one asks **Detach**, **Stop** or **Cancel**. When you quit, every agent on a host, working or idle, keeps running, and the quit prompt says which hosts they are on; after a relaunch each comes back as a tab. Temple never stops anything later on its own: a session it could not stop when you closed it (the host didn't answer, or another terminal is attached) is left running, and Temple says so.
- **Stopping what is still running.** Settings ▸ Hosts ▸ **Sessions on <host>…** lists every session Temple started on that host and still tracks, with **Stop** and **Keep**; it is also one click from every "left running" notice. From a terminal on the host, `tmux -L temple ls` lists them and `tmux -L temple kill-session -t temple-<handle>` stops one. Temple never lists or stops a session it didn't start, and never touches your own tmux sessions.
- **A new Codex session on a host links itself, or asks.** Codex picks its own session ID, and by default it writes the session file through a background process rather than the one Temple started, so Temple looks for sessions begun in that folder since. When exactly one matches and you have typed into the tab, Temple says yes for you and the tab says "Linked to “<first prompt>”, the only Codex session started in this folder since this tab opened. If that’s wrong, Discard stops it and removes it from Temple.", with **Discard**, which stops that session and removes it. With more than one, or once the tab has asked, the tab asks "Is this the session?" with the first prompt, the time and the folder: **Yes, that's it** or **Not this one**. Add `--no-daemon` to Codex's arguments and Temple identifies the session on its own (the Hosts card says so); those arguments apply to Codex on this Mac too.
- **Codex sessions no longer show "(no prompt)".** In the sidebar and History, a Codex session is titled from the first prompt you typed, until Codex or you name it. The instructions Codex adds for a folder's `AGENTS.md` are never taken for your prompt.
- **The sidebar follows the tab you are in.** When a new Codex session learns its ID while its tab is open, its row is selected; a tab with no session yet selects no row rather than leaving the last one highlighted.

## Known limits

- A host needs tmux 3.2 or newer to start sessions; Test connection says when it doesn't have it. With tmux older than 3.3 (Ubuntu 22.04 ships 3.2a), Codex shows its own default colours instead of Temple's, and a drag-selection doesn't reach the Mac clipboard (⇧-drag still selects in Temple's own terminal).
- Claude Code has to be logged in on the host itself. If it isn't, run `claude` there once (in a Temple tab on that host, or in any terminal) and log in.
- Scrollback belongs to tmux on a host: the wheel scrolls tmux's history, and the first key you type returns to the prompt. ⌘F searches what the tab has shown since it connected.
- Temple shows only the sessions it started or opened on a host; it does not list or import a host's other sessions. Hosts have been tested on Linux only. The usage meter and Reveal in Finder stay on this Mac, and `temple sessions new` starts sessions on this Mac only.

## Upgrading

- Nothing in Temple's database changes. What Temple knows about sessions on hosts lives in a file of its own (`remote-state.sqlite`), created only once you use a host, and your host list in Temple's settings.
