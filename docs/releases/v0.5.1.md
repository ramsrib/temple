## What's new

- **Recent sessions stay in the order you used them.** Quitting Temple makes every open Claude session write a little bookkeeping to its transcript on the way out, and v0.5.0 read that as activity: after a relaunch, every session that had a tab open looked used at the same second, and ⌘K and recent projects put week-old sessions next to yesterday's. Temple now dates a session by the last timestamped entry in its transcript.
- **⌘P remembers your recent projects across a relaunch.** The project switcher used to forget its order on every launch and fall back to tab order behind the project you quit in. It now comes back the way you left it.
- **The project switcher no longer lands mid-title-bar.** On a launch with no saved window size and the sidebar hidden, the title bar's project switcher could sit in the middle of the band, away from the sidebar button, until the window was resized. It now follows the layout as it settles.
- **One Keychain prompt for Claude usage, not two.** Allowing Temple to read Claude Code's sign-in for the usage meter was followed by a second prompt seconds later. Temple now keeps the token it read for as long as it is valid instead of reading the Keychain on every refresh.

## Upgrading

- The first launch clears the activity dates v0.5.0 recorded for sessions that are not archived and fills them again from each transcript, so the order corrects itself. A session whose transcript is gone sorts by when you last opened it. Temple's automatic archive still measures its week of idleness from the old date until a new one is read, so nothing is archived sooner because of this.
- v0.5.0 can still open your data after this release.

## Known issue

- Claude Code rewrites its Keychain entry each time it renews its sign-in, and macOS can drop Temple's access when it does. The usage meter may then ask again, once, after a renewal.
- History still dates sessions by when their transcript file last changed, so sessions open at quit can show under today there.
